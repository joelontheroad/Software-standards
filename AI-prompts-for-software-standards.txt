1. Problem Statement & Root Cause Diagnosis
User Scenario
The user transcribed and burned a video. They subsequently opened the generated .ass subtitle file (katie-first-ad-1080-1080-2.4-bug_voice_titles.ass) directly from outside the program using the operating system's file manager / text editor to make edits. Upon returning to Voice Highlighter:

Clicking the "Burn Video" button resulted in "nothing happening" (no burn progress, no visual change).
Clicking "Browse" in the Video Source Section to reload the video file caused the "Burn Video" button to become inactive / disabled, despite the .ass file residing directly alongside the video.
Refreshing the browser page produced the exact same inactive outcome.
Root Cause Analysis
A. Why "Nothing Happened" When Clicking "Burn Video"
Undeclared editorState Reference (JavaScript ReferenceError): In 
frontend/app.js
:

javascript

const effectiveAss = editorState.assPath || state.existingAssPath;
if (!effectiveAss && !editorState.currentContent) { ... }
editorState is not declared anywhere in app.js or index.html. In JavaScript, evaluating an undeclared identifier throws an unhandled ReferenceError: editorState is not defined. Because this occurred inside the click event listener prior to any HTTP request or error handler, browser execution stopped abruptly and silently—giving the exact appearance of "nothing happening." (Similar undeclared references exist at lines 2597, 2834, 2855, 2870, 3175, and 3573).

Completed Task ID Collision in Polling: In 
frontend/app.js

javascript

const burnTaskId = state.currentTaskId || editorState.taskId || (`burn_${Date.now()}`);
state.currentTaskId was retained from the earlier completed transcription job. When the frontend started polling /api/status/${burnTaskId}, the server immediately returned { status: "completed" } from the previous run. The polling handler immediately cleared the interval and hid the progress thermometer after 1000ms.

Filesystem Path vs. API URL Desynchronization: In
